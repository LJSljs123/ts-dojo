## 九、v3.6：模型工坊——自己搓模型，跑完全实验流程

**定位**：从「做题」到「做研究」的最后一步。学习者在 `#/studio` 写一个带训练逻辑的 predict 函数（示例模板教「只用 history 做网格搜索选参」），跑完**验证集迭代 → 最终测试评测 → 报告与留档**的完整实验流程——这正是 m1/m7 课程里讲的「模型选择只看 val、test 只碰一次」的实操化。

- **实验协议（平台强制，防泄漏 by construction）**：数据集按 15%/15% 切 val/test（12–48 点夹取，train 不足 24 显式报错）；① 验证集评估可反复；② 最终评测用 train+val 重新拟合、test 打分，**同一代码哈希的 test 评测次数如实记录并在报告里警示**（次数>1 提示「test 正在变成另一个验证集」）。
- **沙箱零改动**：合成 problem/dataset 走 judge.evaluate——Worker 隔离、1500ms/8000ms 超时、RE 行号定位、基线全家桶（5 条）全部继承判题语义，没有任何新执行路径。

## 十一、v3.8：P17 促销协变量（第一个带外生上下文的题）

**主线**：前面 16 题都在教「从序列自身挖结构」，P17 教一件序列自身挖不出来的事——**外部日历**。促销日的尖峰不是季节，是事件；它同时污染历史、又必须被乘回未来。

- **P17 促销日历（`p17-promo-covariate`，提高，100 分）**：日销量 730 点（周季节 + 促销间隔 8–11 天），horizon 14，MSE，threshold 0.9，passScore 60。题目把 `ctx.promoDays`（绝对下标）交给选手，要求同时做两件事：**清洗历史促销尖峰**（否则季节基线被抬高，所有非促销日一起高估）与**修正未来促销日**（否则未来促销日全低估）。
- **参考解**（`solPromoCovariate`）：两步——先按「促销日 / 同相位非促销日」的中位数比估出乘性倍数（实测 1.609），把历史促销日除回去，跑季节朴素得到基线，再把未来促销日乘回倍数；未来下标用 `h % m` 取相位，避免 `horizon > season` 时越界。实测 100 分。
- **模板**：纯季节朴素（促销日历拿到手却没用），55 分 WA。

## 十二、v3.9：P18 渠道拆分（聚合会掩盖周期）

**主线**：前 17 题都在教「怎么从一条序列里挖结构」，P18 教一件序列自身给不出来的事——**信息粒度**。总量把两个不同节律的渠道叠在一起，于是任何一个单一周期的模型都只能拟合其中一半；模型再复杂也没用，因为缺的不是模型能力，是拆开这件事。

- **P18 渠道拆分（`p18-channel-mix`，提高，100 分）**：日销量 730 点 = 门店（周周期、周末约工作日 1.6 倍、缓慢增长、3% 噪声）+ 企业（30 天结算周期、27 天平段 + 月末 3 天冲量约 2.2 倍、增长更快、4% 噪声）逐日相加。horizon 14，MSE，threshold 0.9，passScore 60。两路分量以 `ctx.parts = [{name, period, values}]` 交给选手，`values` 按 `history` 长度截断、下标对齐（不含未来）。
- **参考解**（`solChannelBottomUp`）：各渠道按自己的 `period` 取「上一个周期同日」，再逐点相加。实测 100 分（ratio 0.066）。
- **模板**：总量上的季节朴素（`ctx.season` 只描述门店），55 分 WA —— 它正好就是本题的最优基线。
- **教学梯度（四个数字全部写成断言）**：
  | 做法 | 分数 | 说明 |
  |---|---|---|
  | 模板：总量 + 季节朴素 m=7 | 55 | 打平最优基线 |
  | 总量 + 季节朴素 m=30 | 55 | 补上企业，丢掉门店的周节律 |
  | 总量 + P6 的 Holt-Winters 原样搬来 | 41 | 水平项去追尖峰，追不上还把平段带偏 |
  | 拆开但企业当常数水平 | 23 | 窗口里 3 天冲量全漏，比不做还低 |
  | 拆开 + 各自周期 | 100 | 唯一过线的做法 |
  **换周期、换模型都撞在 55 分这堵墙上，只有换信息粒度能过。**
- **数据形态（关键，两次否决后的结论）**：不是「让尖峰更陡」，而是让两个周期各自的误差量级相当。尖峰太缓 → HW 能跟住（59 分，离通过线只差 1 分）；尖峰陡但周节律弱 → `m=30` 正好复现尖峰（99 分）。最终取 `amp=1.4 / 峰高 1.9`，两边都撞墙。细节见 `v3-architecture.md` 12.10。

- **新工具 `tools/stamp-assets.js`**：把每处 `?v=` 换成该资源内容的 sha1 前 8 位。三种用法——直接跑（改写）、`--check`（过期退出码 1）、`require()`（测试复用，不落盘）。只改 `?v=` 的值，不动引用顺序、不增删标签。
- **为什么不用手写版本号**：零构建项目里版本号必然出现三份副本（`index.html` / changelog / README），没有任何机制保证同步——和上一轮 README 数字漂移同一个病根。内容哈希是单一来源，忘不掉。
- **踩到的坑（已修）**：第一版对原始字节算哈希，在「注入漂移 → `git checkout` 还原」的验证动作里暴露——`core.autocrlf=true` 把工作区改成 CRLF，字节变了内容没变，还原后 52 处 token 全部「过期」。修法：先按 LF 归一化（`replace(/\r\n/g, '\n')`）再算哈希。否则每个新克隆一落地就是红的，跑一遍打标工具又生成一个纯换行符的空提交。
- **新增 `tests/qa/assets-version.test.js`（3 条）**：① token 等于内容哈希、无裸引用；② 引用不 404；③ `assets/` 下无孤儿文件 + `js ≥ 40` / `css ≥ 3` 下界。第 ③ 条防的是「扫描器失效 → 一致性检查全绿」的假象；一致性断言必须配「至少扫到这么多」的下界。
- **验证用例本身有效**：往 `chart.js` 末尾追加一行注释 → A01 立刻红；`git checkout` 还原 → 三条全绿。前后各跑一次。
- **流程**：改任何 `assets/` 下的文件都要重跑打标工具（刻意的摩擦，保证「源码变了」和「引用变了」不分家）。哈希只保护子资源，`index.html` 自身仍需服务器 `no-cache`。
- **文档**：README「改了源码后如何更新单文件版」补打标步骤与原因、目录树补工具、自测表补一行、加题流程补最后一步；`v3-architecture.md` 新增 12.12。
- 验证：235 条全绿 0 skip；standalone-check 全绿（833.1KB / 48 脚本）；README 口径自检 ✓。

| 位置 | 现象 | 性质 |

## 二十、v3.17：srcdoc 宿主里一个链接把整个应用卸载

**起因**：用户反馈「我点击没一个能用呢」。这句话优先于任何测试结论。

### 20.1 先证明应用本身没坏

用 `Input.dispatchMouseEvent` 派发**真实鼠标事件**（不是 `el.click()`），13 条路由逐控件点 **156 次**：只有 8 次「无反应」，且全是点击当前所在页的导航项（`class="on"`），本来就是正确的无操作。

顺带暴露上一轮的方法论漏洞：**`el.click()` 绕过命中测试**，只证明「处理器被调用了」，不证明「真人点得动」。

### 20.2 换宿主：应用被卸载

预览面板不打开文件，而是把 HTML 塞进 `<iframe srcdoc>`。实测点顶栏「题库」：

| | 点击前 | 点击后 |
|---|---|---|
| iframe URL | `about:srcdoc#/` | `file:///.../host.html#/problems` |
| `window.TSJ` | 60 个键 | 0 |
| `#view` | 3677 字符 | 不存在 |

**机理**：`srcdoc` 文档没有自己的 URL，片段按**父页面 base** 解析，`href="#/problems"` 变成另一个 URL → 浏览器执行真实导航 → iframe 指向宿主页 → 应用卸载。

### 20.3 修法

| 位置 | 问题 | 修法 |
|---|---|---|
| 全站 `<a href="#/x">` | srcdoc 里被解析成父页 URL | 新模块 `app/links.js` 接管点击，改赋值 `location.hash`（只改片段，不解析） |
| `.ds-skip-link` (`#view`) | 被路由解析成未知视图 → 兜底渲染成题库 | 按锚点语义：滚动 + 聚焦，不碰 hash |
| `method-detail.js` | 方法不存在时 `location.replace('#/methods')`，同类问题 | 改 `location.hash` |

边界（不接管）：修饰键点击、`target=_blank`、`download`、外链、找不到目标的自定义锚点。

### 20.4 新增 `tests/qa/srcdoc.test.js`（4 条）

L01 启动 · L02 点导航后应用还在 · L03 连续跳转 · L04 跳转链接只移焦点不改路由。

- **现场构建单文件版**：`build-standalone.js` 导出 `buildHtml()`，测试不读已提交产物 —— 否则改了源码却测旧产物，是 12.18 那种假通过。
- `cdp.js` 的 `waitReady` 加 `readyExpr` 参数：宿主页的 `TSJ` 在 iframe 里，默认判据（顶层窗口）会一直超时。
- 注入验证：把 `links.js` 的接管去掉 → L02/L03 立刻红，报错正是「点击后 iframe 被导航到了 host.html —— 应用已被卸载」。
